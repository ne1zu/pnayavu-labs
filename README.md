# 🏥 Система Управления Сетью Клиник (Clinic Management System)

![Visual Studio](https://img.shields.io/badge/IDE-Visual%20Studio-purple.svg?style=flat-square&logo=visual-studio)
![OOP](https://img.shields.io/badge/Paradigm-OOP%20%7C%20Generic-brightgreen.svg?style=flat-square)

Комплексное консольное приложение на C++ для управления сетью медицинских центров. Проект разработан в рамках цикла лабораторных работ и демонстрирует глубокое понимание принципов объектно-ориентированного проектирования (SOLID, DRY) и обобщенного программирования.

## 📋 Описание проекта

Система позволяет управлять филиалами клиники, медицинским и административным персоналом, базой пациентов, каталогом услуг и записями на прием. В проекте реализовано интерактивное консольное меню для демонстрации всей заложенной бизнес-логики.

---

## 🚀 Эволюция проекта (Выполненные лабораторные работы)

### 🔹 Лабораторная работа №1: Классы и Объекты
* Спроектированы базовые сущности предметной области: Врач, Пациент, Услуга.
* Создан управляющий класс `Filial` (композиция), содержащий списки объектов.
* Реализованы инкапсуляция, конструкторы, геттеры и сеттеры с валидацией данных (например, защита от отрицательного опыта работы или цены).

### 🔹 Лабораторная работа №2: Перегрузка операторов и Дружественные функции
* Перегружены операторы сравнения (`==`, `<`, `>`) для реализации бизнес-логики (сравнение врачей по опыту, пациентов по возрасту).
* Перегружены операторы потокового ввода/вывода (`<<`, `>>`) для удобной работы с консолью.
* Реализованы операторы `+=` и `-=` в классе `Filial` для назначения и увольнения сотрудников.
* Добавлены дружественные функции (`friend`) для поиска объектов внутри закрытых коллекций филиала.

### 🔹 Лабораторная работа №3: Наследование
* Выделен абстрактный базовый класс `Person`, содержащий общие атрибуты (ID, Имя) и методы.
* Создана иерархия классов: `Doctor`, `Patient` и `Administrator` наследуются от `Person`.
* Устранен дублирующийся код (принцип DRY), реализована вынесенная логика генерации уникальных ID.

### 🔹 Лабораторная работа №4: Полиморфизм и Абстрактные классы
* В базовый класс `Person` добавлены чисто виртуальные методы (`getEntityType`, `classify`).
* Настроен виртуальный деструктор для безопасного управления памятью.
* Реализован **динамический полиморфизм**: возможность обрабатывать Врачей, Пациентов и Администраторов в едином цикле через коллекцию умных указателей `std::shared_ptr<Person>`.
* Специфическое действие `classify()` выдает разный результат в зависимости от фактического типа объекта в памяти (Run-time).

### 🌟 Лабораторная работа №5: Шаблоны и Обобщенное программирование (Generics)
* Разработан полностью независимый от предметной области шаблонный контейнер `Collection<T>`.
* Контейнер поддерживает добавление, удаление (по индексу, значению, предикату), безопасный доступ с обработкой исключений `std::out_of_range` и вывод содержимого.
* Реализованы **глобальные шаблонные алгоритмы**:
  * `findFirst` — поиск первого совпадения по критерию.
  * `findAll` — фильтрация коллекции.
  * `countIf` — подсчет элементов по предикату.
  * `findMax` — поиск максимума на основе перегруженного `operator>`.
* Доказана независимость шаблонов: алгоритмы успешно работают как с пользовательскими классами (`Doctor`, `Appointment`), так и с примитивными типами C++ (`int`, `std::string`).

## 🏗️ Архитектура системы (UML)

Проект строго следует принципу **IS-A** (наследование) и **HAS-A** (агрегация/композиция):
1. **Базовый абстрактный уровень:** `Person`
2. **Уровень специализации:** `Doctor`, `Patient`, `Administrator`
3. **Независимые компоненты:** `Service` (Услуга), `Appointment` (Запись на прием)
4. **Уровень контейнеров:** Универсальный шаблон `Collection<T>`
5. **Уровень управления:** `Filial` (Агрегирует в себе коллекции всех сущностей)

## 🛠️ Сборка и запуск

Проект не имеет внешних зависимостей и использует исключительно стандартную библиотеку C++ (STL).

**Требования:**
* Компилятор с поддержкой **C++17** или выше.
* Visual Studio / CLion / GCC.

**Запуск через Visual Studio:**
1. Откройте файл решения (если есть) или создайте пустой проект C++.
2. Добавьте все файлы из папок `include` и `src` в проект.
3. *Важно:* Убедитесь, что файл `collection.tpp` не компилируется как отдельный объектный файл (в свойствах файла `Item Type` -> `Does not participate in build`).
4. Нажмите `Ctrl + F5` (Запуск без отладки).
