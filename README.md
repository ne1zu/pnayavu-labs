Комплексное консольное приложение на C++ для управления сетью медицинских центров. Проект разработан в рамках полного цикла лабораторных работ (Лабы 1–8) и демонстрирует глубокое понимание принципов объектно-ориентированного проектирования (SOLID, DRY), обобщенного программирования (шаблоны), обработки исключительных ситуаций, персистентности данных (сериализация) и виртуозного владения стандартной библиотекой шаблонов (STL).

## 📋 Описание проекта

Система позволяет управлять филиалами клиники, медицинским и административным персоналом, базой пациентов, каталогом услуг и записями на прием. В проекте реализована надежная отказоустойчивая архитектура, исключающая аварийное завершение программы при ошибках, автоматическое сохранение и восстановление состояния базы данных между сеансами работы, а также встроен мощный аналитический движок на базе алгоритмов STL.

## 🚀 Эволюция проекта (Выполненные лабораторные работы)

### 🔹 Лабораторная работа №1: Классы и Объекты
* Спроектированы базовые сущности предметной области: Врач, Пациент, Услуга.
* Создан управляющий класс `Filial` (композиция), агрегирующий объекты.
* Реализованы инкапсуляция, конструкторы, геттеры и сеттеры с валидацией входных данных.

### 🔹 Лабораторная работа №2: Перегрузка операторов и Дружественные функции
* Перегружены операторы сравнения (`==`, `<`, `>`) для бизнес-логики (сравнение врачей по стажу, пациентов по возрасту).
* Перегружены операторы потокового ввода/вывода (`<<`, `>>`) для интеграции с консолью.
* Реализованы операторы `+=` и `-=` в классе `Filial` для добавления и удаления сотрудников/пациентов/услуг.
* Реализованы дружественные функции (`friend`) для безопасного поиска объектов внутри закрытых хранилищ филиала.

### 🔹 Лабораторная работа №3: Наследование
* Выделен абстрактный базовый класс `Person`, объединяющий общие атрибуты (ID, Имя) и базовые методы.
* Создана чистая иерархия наследования (IS-A): `Doctor`, `Patient` и `Administrator` унаследованы от `Person`.
* Устранено дублирование кода (принцип DRY), реализована централизованная выдача уникальных идентификаторов.

### 🔹 Лабораторная работа №4: Полиморфизм и Абстрактные классы
* В интерфейс `Person` добавлены чисто виртуальные методы (`getEntityType`, `classify`) и виртуальный вывод (`printInfo`).
* Предусмотрен виртуальный деструктор для гарантии безопасного освобождения ресурсов при полиморфном удалении.
* Реализован **динамический полиморфизм**: массовая обработка разнородных объектов через коллекцию умных указателей `std::shared_ptr<Person>`.
* Полиморфное действие `classify()` выдает результат, зависящий от фактического типа объекта в памяти во время выполнения (Run-time).

### 🔹 Лабораторная работа №5: Шаблоны и Обобщенное программирование (Generics)
* Разработан полностью универсальный шаблонный класс-контейнер `Collection<T>`.
* Контейнер поддерживает добавление, удаление (по индексу, значению, предикату), безопасный доступ с обработкой выхода за границы и циклический обход (`begin()`/`end()`).
* Реализованы **глобальные шаблонные алгоритмы**:
  * `findFirst` — поиск первого элемента по критерию.
  * `findAll` — фильтрация подмножества объектов.
  * `countIf` — подсчет элементов по предикату.
  * `findMax` — поиск максимального элемента по `operator>`.
* Доказана независимость шаблонов от предметной области (успешная работа со стандартными типами `int` и `std::string`).

### 🔹 Лабораторная работа №6: Обработка исключительных ситуаций (Exceptions)
* Спроектирована разветвленная иерархия собственных классов исключений на базе `std::runtime_error` во главе с `ClinicException` (12 специализированных классов: `InvalidDataException`, `CapacityExceededException`, `ScheduleConflictException`, `IndexOutOfRangeException` и др.).
* Логика валидации вынесена на нижний уровень (генерация через `throw` в конструкторах, сеттерах и операторах).
* На верхнем уровне (`Lab.cpp`) реализован главный безопасный диспетчер `runMenuSafely`, перехватывающий ошибки через полиморфные блоки `try-catch` (от частных к общим и `catch(...)`).
* Гарантирована устойчивость к сбоям: программа не завершается аварийно, корректно выполняет раскрутку стека (Stack Unwinding) и сохраняет транзакционную целостность объектов при ошибках.

### 🔹 Лабораторная работа №7: Потоки и файловый ввод-вывод (Serialization & Logging)
* Спроектирован модуль долговечного хранения данных (Data Access Layer) в соответствии с принципом **SRP**:
  * `DataStorage` — сохранение (`save`) и восстановление (`load`) полного состояния клиники в файл `clinic_state.txt`. Разработан собственный текстовый формат с разделением на секции и контролем ссылочной целостности (восстановление связей между филиалами, врачами и записями по ID).
  * `Logger` — ведение хронологического журнала событий (`clinic_log.txt`) в режиме `std::ios::app` с точными отметками времени (`currentTimestamp()`).
  * `ReportWriter` — экспорт читаемого структурированного отчета о деятельности клиники в `clinic_report.txt`.
* Реализована строгая валидация файлов: проверка заголовков версий, контроль формата строк, обнаружение повреждений и несовпадения ID с генерацией исключений (`FileOpenException`, `FileFormatException`, `FileIOException`).
* Реализованы механизмы автозагрузки при старте и автосохранения базы при выходе из программы.

### 🌟 Лабораторная работа №8: Стандартная библиотека шаблонов (STL)
* Разработан высокопроизводительный аналитический модуль `StlAnalyzer`, оперирующий рабочей копией данных и не нарушающий целостность оригинальной базы.
* Обоснованно применены **5 различных контейнеров STL** под конкретные алгоритмические задачи:
  * `std::vector` — линейные массивы врачей, пациентов и услуг для компактного размещения в кэше процессора и быстрой сортировки.
  * `std::list` — двусвязный список записей на прием (`Appointment`) для мгновенного удаления и отмены записей из середины за $O(1)$ без сдвига элементов и без инвалидации итераторов.
  * `std::unordered_map` — хеш-таблица для поиска врачей по уникальному ID за константное время $O(1)$.
  * `std::map` — красно-черное дерево для автоматической алфавитной группировки врачей по специальностям и подсчета частоты записей.
  * `std::set` — множество для фильтрации дубликатов и быстрого подсчета уникальных обслуженных пациентов.
* Реализован богатый набор стандартных алгоритмов с применением **лямбда-выражений** (захват по значению, по ссылке и смешанный):
  * `std::sort` и `list::sort` — многокритериальная сортировка (по возрастанию/убыванию, по стажу, возрасту, цене, дате).
  * `std::find`, `std::find_if`, `std::copy_if` — линейный поиск и сложная фильтрация данных.
  * `std::min_element` и `std::max_element` — поиск экстремальных значений (самый опытный врач, самый загруженный специалист).
  * `std::count`, `std::count_if` — подсчет объектов по критериям.
  * `std::accumulate` и `std::transform` — подсчет суммарной выручки клиники и длительности всех процедур.
  * Идиома **Erase-Remove** (`std::remove_if` + `erase`) для корректного физического удаления элементов из векторов.
* Добавлен пункт меню **22 «STL Algorithms»** с двумя режимами: интерактивный пользовательский анализ и готовый автоматический тест на сгенерированных данных.

## 🏗️ Архитектура системы (UML)

Проект строго следует принципам **SOLID**, **GRASP** и концепциям объектного взаимодействия:
1. **Базовый абстрактный уровень:** `Person`
2. **Специализированные сущности:** `Doctor`, `Patient`, `Administrator`
3. **Независимые бизнес-компоненты:** `Service` (Услуга), `Appointment` (Запись на прием с контролем расписания)
4. **Уровень обобщенных коллекций:** Пользовательский шаблон `Collection<T>` и алгоритмы обработки
5. **Уровень управления филиалами:** `Filial` (Агрегирует коллекции персонала и записей)
6. **Слой передачи данных (DTO):** Структура `ClinicData` (объединяет все сущности для работы с диском и аналитикой)
7. **Слой персистентности (Файловая подсистема):** `DataStorage`, `Logger`, `ReportWriter`
8. **Слой безопасности:** Иерархия исключений `ClinicException`
9. **Слой аналитики и STL:** Класс `StlAnalyzer`, структура `Statistics` и модуль консольного UI `stl_menu`

## 🛠️ Сборка и запуск

Проект написан на чистом C++ и не требует сторонних зависимостей.

**Требования:**
* Компилятор с поддержкой **C++17** или выше.
* Среда разработки: Visual Studio 2019/2022, CLion или компиляторы GCC/Clang.

**Инструкция для Visual Studio:**
1. Клонируйте репозиторий или откройте папку с проектом.
2. Убедитесь, что все заголовочные файлы (`.h`, `.tpp`) находятся в каталоге `include`, а файлы реализации (`.cpp`) — в каталоге `src`.
3. Убедитесь, что для файла `collection.tpp` в свойствах установлено: `Тип элемента` -> `Не участвует в сборке` (он подключается внутри `collection.h`).
4. Нажмите `Ctrl + Shift + B` для сборки решения.
5. Нажмите `Ctrl + F5` для запуска приложения.

## 💻 Пример использования (Главное меню)

 9. Compare                        # Сравнение объектов (<, >, ==)
10. Delete Object                  # Полное удаление объекта из системы
-------------------------------------------
11. Check Service                  # Проверка доступности услуги (friend)

20. Load State                     # Загрузка состояния из файла

 0. Exit                           # Автосохранение и выход
